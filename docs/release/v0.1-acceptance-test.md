# lim v0.1 Release 验收测试清单

> 本文档是 v0.1 release 前的**人肉测试清单**，用于验证核心功能在真实环境下的表现。
> 每个测试项包含：测试方法 + 期望表现。全部通过后可进入 release 流程。
>
> 详细测试教程见 [functional-testing.md](../functional-testing.md)，本文档是其精简验收版。

## 前置准备

所有测试在项目内的 `manual-test/` 子目录中进行，不污染主项目代码。API key 通过 `lim init` 生成配置文件写入，不使用 `export`。

```bash
cd /path/to/lim

# 1. 构建 release 二进制
cargo build --release
export PATH="$PWD/target/release:$PATH"

# 2. 创建测试 workspace 并初始化
mkdir manual-test && cd manual-test
lim init --provider anthropic
# 期望：创建 .lim/config.toml + AGENTS.md，打印 "Workspace initialized"

# 3. 编辑配置，填入真实 API key（manual-test/ 已 gitignore）
#    打开 .lim/config.toml，把 api_key = "sk-ant-..." 改成你的真实 key
#    如需同时测试 OpenAI，取消注释 [providers.openai] 段并填入 key

# 4. 验证版本嵌入
lim --version
# 期望：lim v0.1.0-<git describe 后缀>（非 "unknown"）

# 5. 验证 provider 配置加载
lim providers
# 期望：列出 anthropic（+ openai 如已取消注释）
```

> **`lim init` 做了什么**：创建 `.lim/` 目录 + 生成 `config.toml` 模板（预填 `--provider` 指定的 provider）+ 生成 `AGENTS.md` 模板（如不存在）。`.lim/` 是 lim 识别 workspace 边界的标识（向上查找 `.lim/` 或 `Cargo.toml`，第一个命中即为 workspace root）。`.lim/` 下的子目录（`loop/`、`daemon/`、`worktrees/`）和 `sessions/` 由 lim 在运行时自动创建。
>
> **关于 `~/.lim/`**：`lim serve --daemon` 模式会在 `~/.lim/lim.pid` 写入 PID 文件、在 `~/.lim/logs/` 写日志——这是 serve 的固有行为（跨 workspace 共享），不受测试 workspace 隔离影响。其余所有测试产生的文件都在 `manual-test/` 内。

## 二、工具调用（4 项）

### 2.1 read 工具

```bash
echo "test content" > test.txt
lim run --provider anthropic --message "读取 test.txt 并告诉我内容"
```

**期望**：agent 调用 `read` 工具，输出包含 "test content"。

### 2.2 write + edit 工具

```bash
lim run --provider anthropic --message '在当前目录创建 hello.rs，内容是 fn main() { println!("hello"); }'
lim run --provider anthropic --message "把 hello.rs 里的 hello 改成 hi"
```

**期望**：文件创建成功，随后 edit 修改成功，内容变为 `println!("hi")`。

### 2.3 shell 工具

```bash
lim run --provider anthropic --message "运行 ls 并告诉我看到什么文件"
```

**期望**：agent 调用 `shell` 工具，输出包含当前目录下的文件列表。

### 2.4 Trust level 限制

```bash
# 默认 workspace trust，尝试写 workspace 外（上级目录）
lim run --provider anthropic --message "在 ../outside-marker 创建一个文件"
# 期望：被 workspace trust 拒绝

# 切换 permissive trust
lim run --trust permissive --provider anthropic --message "在 ../outside-marker 创建一个文件，内容 ok"
# 期望：permissive 允许写入成功
cat ../outside-marker  # 验证内容

# 清理
rm ../outside-marker
```

**期望**：默认 workspace trust 阻止 workspace 外写入；`--trust permissive` 允许任意路径。

## 五、Loop Engineering（4 项）

### 5.1 AlwaysPass verifier

```bash
mkdir -p loop-test && cd loop-test
lim loop --provider anthropic --goal "创建 README.md 内容 Hello World"
```

**期望**：agent 创建文件，goal 状态 `Completed`，`.lim/loop/<goal_id>/` 目录生成。

```bash
# 验证
lim loop --list
lim loop --status <goal_id>
ls .lim/loop/<goal_id>/
# 期望：session-0.jsonl, events.jsonl
```

### 5.2 Command verifier（失败重试）

```bash
cd ../ && mkdir -p cargo-demo && cd cargo-demo
cargo init --name demo

# 写一个故意失败的测试
cat > src/lib.rs << 'EOF'
pub fn add(a: i32, b: i32) -> i32 { a - b }
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn test_add() { assert_eq!(add(1, 2), 3); }
}
EOF

lim loop --provider anthropic --goal "修复 src/lib.rs 让 cargo test 通过" --verify "cargo test" --max-sessions 3
```

**期望**：verify 失败后进入下一 session 重试，直到 pass 或 max-sessions 耗尽。

### 5.3 Budget 限制

```bash
cd ../ && mkdir -p budget-test && cd budget-test
lim loop --provider anthropic --goal "生成 1 到 100 万质数表" --verify "test ! -f primes.txt" --max-sessions 2
```

**期望**：2 个 session 后停止，状态 `BudgetExhausted` 或 `NeedsHuman`。

### 5.4 Goal resume

```bash
cd ../ && mkdir -p resume-test && cd resume-test
# 启动一个长 goal，Ctrl+C 中断
lim loop --provider anthropic --goal "重构项目" --verify "cargo test" --max-sessions 10 &
sleep 10 && kill -INT %1
lim loop --list   # 期望：有 Running 状态的 goal
lim loop --resume <goal_id>
```

**期望**：中断后能 resume 继续执行。

## 六、lim serve + goal daemon（4 项）

### 6.1 serve foreground + goal 提交

```bash
cd manual-test

# 终端 1：启动 serve（前台，仅 goal daemon）
lim serve --protocol none
# 期望：打印 "Mode: foreground" + "Protocol: none" + "Goal daemon: enabled (built-in)"

# 终端 2：提交 goal
cd manual-test
lim goal submit --goal "创建 marker.txt" --workspace .
lim goal list
lim goal status <goal_id>

# 回到终端 1，Ctrl+C 关闭 serve
```

**期望**：serve 持续运行，goal 提交后能 list/status，Ctrl+C 优雅退出。

### 6.2 `[serve]` 配置默认值

```bash
# 在 .lim/config.toml 追加 [serve] 段
cat >> .lim/config.toml << 'EOF'

[serve]
protocol = "none"
mode = "foreground"
EOF

lim serve &
sleep 2
# 期望：使用配置默认值 "none"，而非 CLI 默认 "all"
kill -TERM %1
```

**期望**：不带 `--protocol` 时使用配置值 "none"。

### 6.3 禁用 goal daemon

```bash
# 修改 .lim/config.toml 的 [serve.goal_daemon]
cat >> .lim/config.toml << 'EOF'

[serve.goal_daemon]
enabled = false
EOF

lim serve --protocol none &
sleep 2
# 期望：输出 "Goal daemon: disabled"
kill -TERM %1
```

**期望**：`enabled = false` 生效。

### 6.4 SIGTERM 优雅退出

```bash
lim serve &
SERVE_PID=$!
sleep 2
kill -TERM $SERVE_PID
wait $SERVE_PID; echo "Exit: $?"
```

**期望**：exit code = 0（优雅退出，非 137）。

## 七、Context 文件加载（2 项）

### 7.1 AGENTS.md 自动注入

```bash
cd manual-test && mkdir -p context-test && cd context-test
echo "# Conventions" > AGENTS.md
echo "- 回答必须用文言文" >> AGENTS.md
lim run --provider anthropic --message "hello"
```

**期望**：agent 用文言文风格回答。

### 7.2 自定义 context 配置

```bash
cd context-test

# 在已有的 .lim/config.toml 基础上追加 [context] 段
cat > .lim/config.toml << 'EOF'
default_provider = "anthropic"

[providers.anthropic]
type = "anthropic"
api_key = "sk-ant-..."
default_model = "claude-sonnet-4-20250514"

[context]
files = [{ path = "STYLE.md", search = "fixed" }]
EOF

echo "- 用英文回答" > STYLE.md
lim run --provider anthropic --message "hello"
```

**期望**：agent 用英文回答（受 STYLE.md 影响）。

## 八、错误处理（3 项）

### 8.1 无效 API key

```bash
# 创建一个子目录，用无效 key 的配置文件测试
mkdir -p bad-key-test/.lim
cat > bad-key-test/.lim/config.toml << 'EOF'
default_provider = "anthropic"

[providers.anthropic]
type = "anthropic"
api_key = "sk-invalid-key"
default_model = "claude-sonnet-4-20250514"
EOF

cd bad-key-test
lim run --provider anthropic --message "test"
```

**期望**：报 auth 错误，不重试，退出（非 panic）。

### 8.2 JSONL 损坏恢复

```bash
cp sessions/<id>.jsonl corrupted.jsonl
echo "invalid json line" >> corrupted.jsonl
lim run --resume corrupted.jsonl --provider anthropic --message "test"
```

**期望**：跳过损坏行或报错，不 panic。

### 8.3 Ctrl+C 优雅退出

```bash
lim run --provider anthropic --message "写一篇 1000 字文章" &
sleep 3 && kill -INT %1
```

**期望**：优雅退出，session JSONL 包含已发生的事件。

## 发现问题怎么办

- **P0 阻塞**（panic、数据丢失、核心功能不可用）→ 立即修复，阻塞 release
- **P1 重要**（体验差、边界 case 错误）→ 评估是否阻塞 release
- **P2 轻微**（文案、UI 细节）→ 记录到 [TODO.md](../TODO.md)，v0.2 修复
